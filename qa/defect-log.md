# Finora QA Defect Log

| ID | Severity | Defect | Reproduction | Resolution | Regression evidence | Status |
|---|---|---|---|---|---|---|
| FIN-QA-001 | High | Transfer accepted string amounts such as `"10"`; JavaScript addition could concatenate the destination balance instead of adding a number. | Submit transfer body with a valid account pair and `amount: "10"`. The original controller accepted the input. | Require a finite JavaScript number greater than zero before querying accounts or changing balances. | `accountController.test.js` rejects string amounts; successful-transfer test verifies total balance is unchanged. | Fixed and passing |
| FIN-QA-002 | Critical | Transaction update did not validate the new account's ownership; a transaction could be reassigned to another user's account ID. | Submit PUT for an owned transaction with another user's account ID. The original controller proceeded to reverse the old balance and apply the new effect by ID. | Validate transaction fields and verify the target account is owned by the authenticated user before reversing any balance. | `transactionLifecycleController.test.js` verifies foreign target returns 404 before balance lookup/change. | Fixed and passing |
| FIN-QA-003 | Medium | Transaction create/update accepted weakly typed financial/date/category inputs and could surface database validation as server errors or mutate balances before rejecting an update. | Try string/non-finite amounts, blank categories, unsupported update types, and invalid dates. | Add strict amount/type/category/date validation; run update validation before balance adjustment. | `transactionController.test.js` and `transactionLifecycleController.test.js`. | Fixed and passing |
| FIN-QA-004 | Medium | Registration accepted malformed email addresses and returned HTTP 500 for passwords shorter than the six-character minimum. | POST registration with `not-an-email`, then with a valid email and a five-character password. | Normalize and validate name/email/password before database access; return HTTP 400 for malformed email and short passwords. | `authController.test.js` includes malformed email and short-password regression checks; isolated API matrix confirms both cases return HTTP 400. | Fixed and passing |
| FIN-QA-005 | Low | Rounding the displayed budget percentage before classifying its state could show a warning at 79.5% or exceeded at 99.5%. | With a LKR 1,000 budget, request budget status at LKR 795 and LKR 995 spent. Before the fix, the rounded 80%/100% values triggered early states. | Compare the unrounded usage ratio to the 80% and 100% thresholds; display percentage to one decimal place. | `budgetController.test.js` verifies 79.5%, 80%, 99.5%, and 100% boundaries. The red test failed before the change and passed after it. | Fixed and passing |

## Notes

FIN-QA-001 and FIN-QA-005 were reproduced as failing unit tests before their fixes. FIN-QA-002 and FIN-QA-003 were confirmed through source inspection and regression tests designed to fail against the original controller flow. The live MongoDB integration suite also exercises two-user isolation across representative transaction and transfer operations. FIN-QA-004 was reproduced in the isolated API matrix and then verified after the fix. GitHub Issues are disabled for this repository (the API returns HTTP 410), so this defect log is the available issue-tracking record.
